# デモデータ管理

## 目的

統合版の各チーム画面を確認できるよう、今日・過去・未来の勤務調整データを再現可能なバッチとして追加します。生成データには名前の接頭辞だけでなく `demo_data_batches` と `demo_data_records` による所有権記録が付きます。

## 月次生成範囲と最低密度

生成日は `Time.zone.today` を基準にし、基準月の6か月前から12か月後まで、両端を含む19か月へ分散します。各月には、画面を移動して確認できるよう、次の最低件数を決定的に用意します。

| 種別 | 各月の最低件数 | 確認できる画面 |
| --- | ---: | --- |
| 勤務依頼 | 2 | 依頼一覧・事業者画面・ガントチャート |
| 勤務可否 | 4 | 勤務可否カレンダー・候補者一覧 |
| 下書き割当 | 1 | 仮割当の評価・シフト表 |
| 確定割当 | 1 | 確定一覧・シフト表 |
| 変更履歴 | 2 | 変更履歴の既読／未読 |

全体で事業者7件、スキル9件、スタッフ20件を作成し、現在月を含む19か月に勤務依頼45件、勤務可否81件、割当44件、変更履歴99件を配置します。現在月は固定シナリオ7件を追加するため勤務依頼9件、勤務可否9件、割当8件となり、評価OK、時間重複、スキル不足、人員不足、確定済みを一度に確認できます。勤務依頼・勤務可否・割当・変更履歴は同じ月の関連レコードへ紐づけ、候補判定に使うスタッフには対応する勤務可能時間とスキルを用意します。

## 確認シナリオ

| 業務画面 | 生成する確認状態 |
| --- | --- |
| 仮割当の評価・確定 | 評価OK、スキル不足、時間重複、人員不足、下書き・確定済み割当 |
| 変更履歴 | `pending` と `reviewed`、依頼・勤務可否・割当の記録 |
| 事業者の勤務依頼 | 今日を中心とした新規依頼、編集対象、過去・未来、取消済み |
| 管理者ガントチャート | 複数事業者の日付分散、1時間以上の依頼 |
| 人員状況 | 検索語に使える事業者・依頼・スキル、不足あり／なし、候補あり／なし |
| シフト表・CSV | 下書きと確定、同一スタッフの重複トラック、交通手段・集合場所メモ |
| 勤務可否カレンダー | `available`、`unavailable`、現在月の固定確認ケース |
| 全体案内 | 既存各画面へのリンクとデモ管理入口 |

## 管理画面

`/admin/demo_data` は専用PIN（現在はコード内の `1234`）で解除します。PINは入力値を永続化せず、サーバー側で比較した後にセッションへ許可状態だけを保存します。管理画面では再ロックもできます。

- `POST /admin/demo_data/batches`: ランダムなデモバッチを追加
- `PATCH /admin/demo_data/reset`: 明示確認付きで生成データを削除し、基準バッチを追加
- `DELETE /admin/demo_data`: 明示確認付きで生成データだけを削除

全てのフォームはRailsのCSRFトークンを含みます。リセット・削除はサーバー側でも確認値を検査します。

## 削除安全性

削除は所有権テーブルから取得したIDに限定し、変更履歴、割当、勤務可否、勤務依頼、スタッフスキル、スタッフ、スキル、事業者の順に依存関係を解消します。手動データや、所有権記録のない既存seedデータは対象外です。処理はトランザクションとPostgreSQLのトランザクションスコープ advisory lock で囲み、失敗時は全体をロールバックします。

## 運用上の注意

このPINは公開デモ向けの偶発操作防止であり、本番の認証・権限管理の代替ではありません。データ確認後は管理画面の「ロックする」を押してください。
